# SignalForge 策略筆記撰寫框架

這份文件是新增或更新策略筆記時的固定框架。Agent 在撰寫任何策略筆記前，必須先讀取這份文件，並依照這裡的段落順序與寫作邊界整理內容。

策略筆記的目標是讓讀者理解「這個策略怎麼看市場、什麼時候進場、什麼時候出場、哪些術語要先懂」。策略筆記不是回測報告，也不是實驗紀錄。

## 寫作原則

- 一種策略一份筆記。
- 先解釋專業術語，再講策略規則。
- 用白話描述策略直覺，再補上程式中的精確條件。
- 進出場要寫成狀態切換，而不是只列公式。
- 圖片必須用來解釋策略判斷，不得暗示績效保證。
- 保留策略相關內容即可，不放回測紀錄型段落。

## 不要放進策略筆記的段落

策略筆記不要放這些段落：

- `策略狀態`
- `資料與回測`
- `目前結果`
- `變更紀錄`

這些內容應該留在實驗紀錄、回測報告或專案進度筆記，不要混進策略說明筆記。

## 各段落寫法

### 先懂這些詞

用條列解釋讀者在這份筆記裡會遇到的專業詞。每個詞都要用白話說明，不要只翻譯英文。

至少要檢查是否需要解釋：

- 策略使用的指標，例如 SMA、VWAP、RSI、z-score。
- 策略狀態，例如 long-only、target_position、warmup。
- 門檻或分數，例如 threshold、entry_z、exit_z、score。
- 特殊計算方式，例如 rolling window、rolling VWAP、rolling standard deviation。

### 策略假設

說明這個策略相信市場中存在什麼現象。例如：

- 趨勢策略：短期均線高於長期均線，可能代表趨勢轉強。
- 均值回歸策略：價格離平均成本太遠，可能會往平均回來。
- 多因子策略：多個條件同時偏多，訊號品質可能高於單一指標。

這段只講策略直覺，不放回測數字。

### 進出場條件

先用白話說明，再列程式條件。必須清楚回答：

- 什麼情況不交易。
- 什麼情況從空手變成持有，這才是進場。
- 什麼情況維持持有，不要誤寫成每天重新進場。
- 什麼情況從持有變回空手，這是離場或狀態歸零。
- 如果目前 CLI 只支援 long-only，要明確說明不討論 short。

如果策略規則容易混淆，加入小例子或狀態表。

### 主要參數

只列會影響策略判斷的參數，例如：

- window 類參數。
- threshold 類參數。
- entry / exit 門檻。
- long-only 或 short 設定。

不要在這段放資料來源、回測期間、回測 artifact 或實驗結果。

### 股價走勢解說圖

每個策略筆記都要放一張 image generation 產生的股價走勢解說圖。

圖片要求：

- 使用合成走勢或教學式圖表，不使用會被誤認為績效承諾的表現曲線。
- 圖中應標出策略判斷所需的主要線條、門檻、進場點或出場點。
- 圖下方用一小段文字說明圖在表達什麼。
- 必須寫清楚圖片是教學示意圖，不是真實市場資料，也不代表績效保證。

### 風險與限制

列出策略本身的限制，而不是回測結果。例如：

- 哪種市場環境容易失效。
- 哪些參數可能造成過度配適。
- 哪些交易成本或資料品質問題會影響判斷。
- 哪些功能目前還沒有納入，例如停損、停利、部位管理或 regime filter。

### 下一步

列出策略研究接下來可以怎麼補強。下一步要跟策略本身有關，不放例行同步或 commit 記錄。

## 寫作檢查清單

完成策略筆記前，檢查：

- 是否先解釋所有專業術語。
- 是否清楚區分進場、持有、離場。
- 是否保留 image generation 圖片與圖說。
- 是否沒有加入 `策略狀態`、`資料與回測`、`目前結果`、`變更紀錄`。
- 是否沒有暗示真實績效保證。
- 是否維持繁中，程式識別字與 CLI 參數可保留英文。
