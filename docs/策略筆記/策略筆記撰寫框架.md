# SignalForge 策略筆記撰寫框架

策略筆記要讓讀者快速回答五件事：這個策略在做什麼、怎麼跑、程式在哪、改參數去哪裡、目前最新回測是否值得保留。不要把整份實驗紀錄塞進策略筆記；底部只保留表格式最新回測註記，詳細證據仍放在實驗紀錄與 generated artifact。

## 固定段落

請直接複製 [[策略筆記模板]] 的 9 段格式。每份策略筆記的主段落必須依序是：快速定位、目前參數、如何運行、進場流程、出場流程、它想捕捉的 edge、股價走勢解說圖、風險與限制、最新回測註記。

最新回測註記必須用 table，不能用一整段文字塞在一起。

## 不放進策略筆記

| 不放內容 | 放到哪裡 |
|---|---|
| 單次回測結果、PF、IR、MDD 明細 | 策略筆記只放短版最新註記；完整明細放 `docs\04-實驗記錄\Autoresearch 實驗記錄.md` 或 `reports\generated\` |
| keep / discard / compare-only 決策流水帳 | 策略筆記只放最新刪減判斷；流水帳放 `docs\04-實驗記錄\Autoresearch 實驗記錄.md` |
| 工具開發 changelog | `docs\03-程式疊代\Phase 程式疊代紀錄.md` |
| 完整維護地圖 | `docs\01-架構\SignalForge 資料夾與程式碼導覽.md` |

## 檢查清單

- 是否先講專業術語，再講規則。
- 控制規則是否有說明輸出與維護語意，而不是只列 `1.0` / `0.0`。
- 主要參數是否有調整判斷，而不是只寫「視窗」或「門檻」。
- README 只放精簡版；完整版與調參版放在策略筆記的「如何運行」。
- 是否標出實作位置與參數位置。
- 是否有圖解與風險限制。
- 是否在最下方有 table 版最新回測註記，且指向可重跑 artifact。
- 是否避免把實驗流水帳塞進同一頁。
