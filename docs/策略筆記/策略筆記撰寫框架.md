# SignalForge 策略筆記撰寫框架

策略筆記要讓讀者快速回答四件事：這個策略在做什麼、怎麼跑、程式在哪、改參數去哪裡。不要把整份實驗紀錄塞進策略筆記。

## 固定段落

```markdown
---
title: <策略名稱>
tags:
  - project/SignalForge
  - trading/strategy
status: research
updated: YYYY-MM-DD
repo_impl: C:\Projects\signal-forge\<path>
---

# <策略名稱>

## 快速定位

| 問題 | 答案 |
|---|---|
| CLI 名稱 / 參數 | `<name>` |
| 適用資料 | 日線 / intraday / 多股票 |
| 實作位置 | `<path>` |
| 常用工具 | `<command>` |

## 先懂這些詞

用短 bullet 解釋讀這個策略必須知道的術語。

## 策略假設

用 2 到 4 段說明這個策略想捕捉的市場行為。

## 進出場 / 控制規則

用表格或編號流程寫清楚訊號如何產生。

## 主要參數

用表格列出參數、預設值、用途、修改位置。

## 怎麼跑

放精簡版與完整版命令。

## 股價走勢解說圖

![[assets/<strategy-image>.png]]

說明圖片只是教學示意，不代表績效保證。

## 風險與限制

列出資料邊界、可能失效情境、不可誤讀之處。

## 下一步

只寫策略語意或文件上的下一步；實驗結果放到實驗紀錄。
```

## 不放進策略筆記

| 不放內容 | 放到哪裡 |
|---|---|
| 單次回測結果、PF、IR、MDD 明細 | `docs\04-實驗記錄\Autoresearch 實驗記錄.md` |
| keep / discard / compare-only 決策流水帳 | `docs\04-實驗記錄\Autoresearch 實驗記錄.md` |
| 工具開發 changelog | `docs\03-程式疊代\Phase 程式疊代紀錄.md` |
| 完整維護地圖 | `docs\01-架構\SignalForge 資料夾與程式碼導覽.md` |

## 檢查清單

- 是否先講專業術語，再講規則。
- 是否有 CLI 精簡版與完整版。
- 是否標出實作位置與參數位置。
- 是否有圖解與風險限制。
- 是否避免把實驗流水帳塞進同一頁。
