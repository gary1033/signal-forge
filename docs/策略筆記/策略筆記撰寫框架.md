# SignalForge 策略筆記撰寫框架

策略筆記要讓讀者快速回答五件事：這個策略在做什麼、怎麼跑、程式在哪、改參數去哪裡、目前最新回測是否值得保留。不要把整份實驗紀錄塞進策略筆記；底部只保留短版最新回測註記，詳細證據仍放在實驗紀錄與 generated artifact。

## 固定段落

```markdown
---
title: <策略名稱>
tags:
  - project/SignalForge
  - trading/strategy
status: research
updated: YYYY-MM-DD
repo_impl: C:\Projects\signal-forge\<path>
---

# <策略名稱>

## 快速定位

| 問題 | 答案 |
|---|---|
| CLI 名稱 / 參數 | `<name>` |
| 適用資料 | 日線 / intraday / 多股票 |
| 實作位置 | `<path>` |
| 常用工具 | `<command>` |

## 先懂這些詞

用短 bullet 解釋讀這個策略必須知道的術語。

## 策略假設

用 2 到 4 段說明這個策略想捕捉的市場行為。

## 進出場 / 控制規則

用表格或編號流程寫清楚訊號如何產生。至少要說明每個判定點的「輸出」與「維護語意」：這條規則在擋什麼、為什麼存在、改錯時會把策略推向哪種誤讀。

## 主要參數

用表格列出參數、預設值、用途、修改位置。用途欄不能只寫名詞，必須交代調大 / 調小會影響反應速度、交易數、集中度、風險或資料邊界的哪一面。

## 怎麼跑

放精簡版與完整版命令。

## 股價走勢解說圖

![[assets/<strategy-image>.png]]

說明圖片只是教學示意，不代表績效保證。

## 風險與限制

列出資料邊界、可能失效情境、不可誤讀之處。

## 下一步

只寫策略語意或文件上的下一步；詳細實驗結果放到實驗紀錄。

## 最新回測註記（YYYY-MM-DD）

- 最新 artifact：`reports\generated\<artifact>.md`
- 樣本：股票池、時間窗、資料頻率與成本假設。
- 結果：只列 3 到 5 個最能支持刪減判斷的指標，例如 PF / IR / Beat B&H / MDD / rolling gate。
- 刪減判斷：`keep`、`compare-only` 或 `discard`，並用一句話說明 tradeoff。
```

## 不放進策略筆記

| 不放內容 | 放到哪裡 |
|---|---|
| 單次回測結果、PF、IR、MDD 明細 | 策略筆記只放短版最新註記；完整明細放 `docs\04-實驗記錄\Autoresearch 實驗記錄.md` 或 `reports\generated\` |
| keep / discard / compare-only 決策流水帳 | 策略筆記只放最新刪減判斷；流水帳放 `docs\04-實驗記錄\Autoresearch 實驗記錄.md` |
| 工具開發 changelog | `docs\03-程式疊代\Phase 程式疊代紀錄.md` |
| 完整維護地圖 | `docs\01-架構\SignalForge 資料夾與程式碼導覽.md` |

## 檢查清單

- 是否先講專業術語，再講規則。
- 控制規則是否有說明輸出與維護語意，而不是只列 `1.0` / `0.0`。
- 主要參數是否有調整判斷，而不是只寫「視窗」或「門檻」。
- 是否有 CLI 精簡版與完整版。
- 是否標出實作位置與參數位置。
- 是否有圖解與風險限制。
- 是否在最下方有短版最新回測註記，且指向可重跑 artifact。
- 是否避免把實驗流水帳塞進同一頁。
