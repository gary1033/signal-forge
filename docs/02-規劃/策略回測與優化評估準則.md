# 策略回測與優化評估準則

這份筆記是 SignalForge 進行回測、策略優化、參數調整或尋找新策略時的共同判斷基準。任何策略改動都不能只用單一漂亮指標決定 keep；必須同時回答交易 edge、風險、穩健性與可執行性。

> [!warning]
> 這份準則只用於研究與 dry-run 評估，不構成投資建議。`live` 仍維持 dry-run only，不接 broker、不讀 API key、不送真實訂單。

## 使用時機

以下情境都要先參考這份筆記，再決定是否繼續：

- 新增策略或從 TradingView / 論文 / 其他公開來源蒸餾策略。
- 修改進場條件、出場條件、濾網、持有期、冷卻期、停損停利或部位規則。
- 比較不同參數組合，例如 threshold、hold bars、volume multiplier、regime window。
- 判斷回測結果是否可以升級成 Phase 2 候選。
- 判斷某輪 autoresearch 的結果應該 keep、discard 還是只保留為 compare-only。

## 四層評估框架

### 1. 交易 edge

先確認策略是否真的有正期望，而不是只因為單一股票、單一期間或少數大贏家看起來漂亮。

| 指標 | 目標表現 | 解讀 |
|---|---:|---|
| Profit Factor | 初篩 `> 1.2`；升級候選 `>= 1.5`；`> 3.0` 要檢查是否少數大贏家或過擬合 | PF 是 gross profit / gross loss，只能說明贏虧總量比例，不能單獨代表風險低 |
| Expectancy | 扣基本成本後 `> 0` | 期望值比勝率重要；高勝率但平均虧損過大仍是壞策略 |
| Trade count | 單一設定至少 `30` 筆才初步可讀；跨股票/跨期間最好累積 `100-300+` 筆 | 交易筆數太少時，PF、勝率、Sharpe 都容易失真 |
| Win rate + payoff ratio | 兩者必須一起看 | 勝率低可以接受，但平均獲利要足以補償平均虧損；勝率高也不能掩蓋大虧損尾端 |

### 2. 風險與可存活性

PF 改善但最大回撤惡化，不代表策略變好；這通常只是把風險推到更不容易被單一指標看見的位置。

| 指標 | 目標表現 | 解讀 |
|---|---:|---|
| Max Drawdown | 必須在可承受範圍；若惡化，需要明確 tradeoff 理由 | 用來判斷策略是否會在還沒等到長期 edge 前就被回撤打斷 |
| Calmar Ratio | `> 1` 可接受；`> 3` 強；回測 `> 5` 要懷疑樣本不足或曲線擬合 | 年化報酬除以最大回撤，適合補足 PF 看不到的資金曲線風險 |
| Sortino Ratio | 優先補進報表；應看扣成本後 downside risk | 對偏態策略比 Sharpe 更貼近風險，因為只懲罰低於目標報酬的波動 |
| Drawdown attribution | 必須能定位到股票、期間、策略原因與 signal reason | 若不知道回撤來自哪裡，不應繼續疊加濾網或參數 |

### 3. 穩健性與抗過擬合

策略要在不同股票、期間、持有期與成本壓力下保留合理表現。單一最好看的回測不是證據，只是候選。

| 檢查 | 目標表現 | 解讀 |
|---|---:|---|
| 多股票 sweep | 不依賴單一標的；升級候選至少多數股票通過，理想是全部或接近全部通過 | SignalForge 目前以七檔 TWSE common window 作為日線基準池 |
| Walk-forward / OOS | OOS 至少保留 IS 表現的 `50%+` | 低於 50% 多半代表參數或策略形狀只貼合過去 |
| Benchmark relative | 相對 buy-and-hold 或市場基準要有正 active return | 只賺錢但輸給被動持有，策略價值不足 |
| Information Ratio | `0.2-0.3` 已有意義；`0.5` 好；`0.75+` 很強；`1.0` 屬例外強 | 衡量 active return / tracking error，適合比較策略是否真的比 benchmark 有價值 |
| Deflated Sharpe / PBO 意識 | 測很多參數或策略時，不能只報最好的 Sharpe 或 PF | 測試次數越多，偶然找到漂亮回測的機率越高 |

### 4. 可執行性與成本

策略必須在合理交易成本、滑價與資料限制下仍有 edge。SignalForge 目前不做真實下單，但回測仍要先把成本敏感度放進評估。

| 檢查 | 目標表現 | 解讀 |
|---|---:|---|
| Cost stress | 1x、2x、3x 成本後 expectancy 仍為正；PF 不應跌破 `1.0` | 高 turnover 或短持有期策略特別容易被成本吃掉 |
| Turnover / overlap | overlap 應可解釋；若用 cooldown 降低 overlap，要同時看 MDD 是否惡化 | overlap 降低不等於風險降低 |
| Fill assumption | 必須說明 signal timing 與成交價格，例如 close confirmed、next open entry、exit close | 避免 look-ahead 或不可能成交假設 |
| Data boundary | 必須清楚資料頻率、時間窗、session、timezone 與是否含 extended-hours | 特別是 ORB / intraday 策略，不定義 session 就不能解讀結果 |

## Keep / Discard Gate

每輪策略研究只做一個聚焦改動，並按以下流程判斷：

1. 寫清楚假設：這輪要改善 entry quality、exit rule、overlap、cost sensitivity、drawdown 還是 benchmark relative return。
2. 固定比較基準：同一批股票、同一時間窗、同一成本設定、同一 hold bars 或明確比較多持有期。
3. 先看 artifact 是否可信：timestamp、reason、position delta、signals CSV、trace summary、trade log 與 summary 必須一致。
4. 再看交易 edge：PF、expectancy、trade count、win rate + payoff ratio。
5. 再看風險：MDD、Sortino、Calmar、drawdown attribution。
6. 再看穩健性：多股票、walk-forward / OOS、benchmark relative、cost stress。
7. 最後決定：
   - **Keep**：edge 改善，風險沒有不可接受惡化，且跨股票/成本/OOS 仍站得住。
   - **Discard**：只改善單一指標、只靠少數大贏家、交易數太少、成本壓力後失效或回撤惡化無法解釋。
   - **Compare-only**：結果有研究價值，但樣本不足、語意未啟用、或還缺風控/成本/OOS 驗證。

## 新策略導入 Gate

新增策略前，先建立或更新策略筆記，並回答：

- 原始來源是什麼；是否為 TradingView、論文、公開文章或自己的研究假設。
- 是否使用 future-looking、pivot、`request.security`、realtime bar、lookahead 或 repaint 風險。
- SignalForge 的 deterministic 版本如何定義：close confirmed、next open entry、固定 hold 或明確 exit。
- 需要的資料頻率、session、timezone、成本假設與 benchmark 是什麼。
- 第一版只實作最小 long-only entry signal，還是已經進入完整持倉 / 風控系統。
- 要和哪個現有 candidate 比較；不能只和空白 baseline 比。

## 目前 SignalForge 基準解讀

截至 2026-05-24，日線多股票主線應把以下候選當成比較錨點，而不是最終策略：

| Candidate | 現況解讀 |
|---|---|
| `confluence-score + hold=10` | 七檔 TWSE common window aggregate PF 達標，但 overlap 偏高 |
| `confluence-score + hold=10 + signal_cooldown_bars=10` | 目前較強風險降低 entry-edge 候選：aggregate PF 約 `2.324`、七檔通過、overlap 降到 `0`；但 target-state OOS 對照中 2024-2026 樣本外 `0/7` beat B&H、avg excess 約 `-143.90%`，所以不能視為完整持倉主候選 |
| `confluence-score + hold=80` 系列 | 可改善相對 buy-and-hold 的落後幅度，但會明顯拉高回撤或重新產生 overlap；目前只保留 compare-only，不升級 |
| `absolute-momentum` | 長期趨勢持有 compare-only 候選。正式 target-state 預設 `126/200` 在 full-window 1x 成本下平均報酬約 `225.78%`、avg excess 約 `-226.95%`，worst MDD 約 `-50.74%`；`vol-target 0.40 + dd-risk-off 25%/120` 可把 full-window 1x worst MDD 降到約 `-44.93%`、avg Sharpe 約 `0.738`。但 walk-forward / OOS 顯示 2024-2026 樣本外原始版本只有 `1/7` beat B&H、avg excess 約 `-105.25%`；疊加風控後變成 `0/7` beat B&H、avg excess 約 `-127.67%`。相對動能股票池篩選掃描 `lookback=63/126/252`、`topN=1/2/3/4/5/7` 後，最佳 active return 仍是近似不篩選的 `topN=7`，因此也不能升級 |
| `portfolio-relative-momentum-rotation` | 目前最強 portfolio-level 候選。七檔股票池原始 `monthly + 21 bars + top3` full-window IR 約 `0.858`，但 `2021-2022` excess 約 `-24.62%`。七檔 `breadth 42/min2` 改善 full IR 到約 `1.017`，但 `2021-2022` 仍負。最新 14 檔 TWSE 股票池中，`breadth 42/min3` full-window return 約 `1974.85%`、excess 約 `1638.67%`、MDD 約 `-23.01%`、IR 約 `1.417`，1x/2x/3x 成本與 6 個 rolling windows 都保持正 excess；concentration guard 顯示 full-window 最大單檔貢獻 `2603` 約 `23.77%`、top-3 約 `55.04%`，但 `roll02` 的 `2603` 約 `68.75%` 且 top-3 約 `82.56%`，仍有分段集中度風險。資料未還原權息、股票池仍小，也尚未做容量/流動性檢查，所以只能標為 current best compare candidate，不是穩定營利證明 |
| ORB 台股 intraday 系列 | 仍有 session / execution-state / one-and-done 語意邊界，尚未成為日線多股票基準 |

因此下一輪如果要優化 `confluence-score`，不要先堆更多 entry filter；優先順序應是：

1. 繼續補齊 summary artifact 的 benchmark-relative risk metrics；portfolio rotation 已有 Information Ratio、tracking error 與 active drawdown，下一步應擴到更多 rolling / OOS 檢查與更大股票池。
2. 對同一七檔 common window 做 1x / 2x / 3x cost stress。
3. 做 drawdown attribution，確認 worst MDD 來自哪檔股票、哪段期間、哪種 signal reason。
4. 對 Absolute Momentum，已知 worst MDD 主要來自 `2454` 的長回撤；`dd-risk-off 20%/60` 已因 worst MDD 惡化而 discard，`25%/120` 與 `vol-target 0.40 + dd-risk-off 25%/120` 暫留 compare-only。walk-forward / OOS 已補上；relative-momentum top-N 股票池已測但沒有改善 benchmark-relative edge。下一步若要做 drawdown control，優先測 re-entry 條件、再平衡門檻、weekly rebalance 或市場 regime，而不是只調 target vol、risk-off bars 或 top-N。
5. 做更多 rolling split 或替代 regime split，確認 edge 不只集中在單一市場狀態。
6. 停損、停利或更多出場規則應分開驗證，不能和 volatility target、walk-forward 或股票池過濾同輪混在一起。
7. 對 portfolio rotation，active risk 指標、rolling window 產生器、可選 market regime filter、可選 volatility target、可選 breadth filter、per-symbol / per-window attribution 與 concentration guard 已補上；14 檔股票池的 `breadth lookback 42 / min positive 3` 是目前最佳折衷。下一步不要只微調 breadth 門檻，應測 concentration-aware 約束（例如 `top_n=4/5`、限制單檔連續入選、sector cap）並檢查 adjusted price、更大股票池或 canary universe 條件。
