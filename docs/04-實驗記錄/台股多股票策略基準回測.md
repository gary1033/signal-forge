# 台股多股票策略基準回測

這輪把策略評估從單一台積電樣本改成多檔台股同時回測，目標是降低只在 `2330` 上找到漂亮 PF 的偏誤。這是研究與回測紀錄，不構成投資建議，也不代表未來績效。`live` 仍維持 dry-run only。

## 樣本設計

### 股票池

本輪使用七檔 TWSE 大型股：

| Symbol | 說明 | 資料檔 |
|---|---|---|
| `2330` | 台積電，既有 anchor | `data/processed/TWSE_2330_1D.csv` |
| `2317` | 鴻海 | `data/processed/TWSE_2317_1D.csv` |
| `2454` | 聯發科 | `data/processed/TWSE_2454_1D.csv` |
| `2308` | 台達電 | `data/processed/TWSE_2308_1D.csv` |
| `2303` | 聯電 | `data/processed/TWSE_2303_1D.csv` |
| `2412` | 中華電 | `data/processed/TWSE_2412_1D.csv` |
| `2882` | 國泰金 | `data/processed/TWSE_2882_1D.csv` |

`2330` 使用既有長資料檔，但 sweep 時以 common window 過濾；其他六檔本輪用 TWSE `STOCK_DAY` 補齊日線資料。

### 共同回測設定

- Window：`2020-01-01` 到 `2026-05-20`
- Timeframe：`1D`
- 策略：`sma-crossover`、`vwap-reversion`、`confluence-score`
- 固定持有期：`1,3,5,10`
- PF 門檻：`>1.50`
- 初始資金：`10000`
- 成本：commission `1 bps` + slippage `1 bps`
- 評估語意：訊號於 bar close 後確認，下一根 open 進場，固定 hold 後以 exit bar close 出場。

## 最主要結論

`confluence-score` 的 `hold=10` 是本輪唯一同時滿足兩個條件的候選：

1. 跨七檔股票 aggregate PF 達到 `2.299`，高於目標 `1.5`。
2. 七檔股票逐檔都通過 `PF > 1.5`，不是只靠單一股票拉高平均。

## 風險判讀

- 這個結果證明 `Confluence Score + 10 bars fixed hold` 是 PF 達標候選，但還不是完整交易系統。
- `overlap` 很高，代表同一段持倉期間內又出現許多新訊號；目前 entry-edge evaluator 會跳過重疊訊號，完整持倉系統必須明確定義忽略、合併、加碼或重新計時。
- `sma-crossover` 的 `hold=10` aggregate PF 也達 `1.818`，但只通過 `5/7` 檔，而且總交易數只有 `45`，樣本強度比 Confluence Score 弱。
- `vwap-reversion` 在多股票日線 baseline 下沒有達到跨股票 PF 目標，暫時不應列為主要優化方向。

## 工程變更

- 新增 `tools\multi_stock_entry_edge_sweep.py`，讓多股票、多策略、多 hold 的 entry-edge sweep 可以用同一個命令執行。
- TWSE fetch 端點改用 `https://www.twse.com.tw/exchangeReport/STOCK_DAY`，因為 `rwd/zh/afterTrading/STOCK_DAY` 在本環境回 `HTTP 307` HTML，無法被既有 JSON parser 穩定處理。
- 新增六檔 TWSE daily CSV 與 manifest，作為多股票回測的可重現資料基礎。

## 下一步

1. 若下一輪要繼續優化績效，優先研究 `Confluence Score` 的持倉語意，而不是先找更多濾網：處理 high-overlap 下的訊號合併、重新計時或冷卻規則。
2. 把 `hold=10` 視為 Phase 2 候選，不要把它塞回 Phase 1 的一日 entry-edge 解讀。
3. 後續若要納入更多台股，應先維持同一個 common window 與同一套 batch sweep，避免回到單一標的最佳化。
